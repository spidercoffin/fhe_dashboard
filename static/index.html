Employee view: customer data is never shown
How to read this page
  1. Every customer record is a ciphertext: an encrypted list of 11 numbers (utilization, late payments, open accounts…). The left list shows only an ID and a fingerprint of that ciphertext.
  2. Computing a score: the scoring server (Worker) multiplies and adds directly on the encrypted numbers using the model's weights. It never has the decryption key, so it never sees the values.
  3. The Custodian is the only component holding the secret key. It decrypts only the results (the score and five factor sub-totals) and hands them to you. It never releases the customer's raw values.
  4. Updating a record (new loan, card, late payment…) adds an encrypted-compatible change to the ciphertext. The old values stay encrypted. Then the score is recomputed to show the impact.
  5. Consent is checked before any computation. Revoke it and every operation is refused (and logged).

Who sees what: You: IDs, ciphertext fingerprints, scores and factor points. Scoring server: only ciphertexts. Custodian: the key, and only releases results.

Audit trail (stand-in for the Hyperledger Fabric ledger)

Every action is logged with a hash of the ciphertext at that moment and the model version, so auditors can verify what was computed and on which data version, without seeing the data. DENIED = blocked by consent.

Glossary

CKKS: a fully homomorphic encryption scheme for approximate real-number arithmetic; results carry tiny rounding error.

Ciphertext: the encrypted record. Without the secret key it is indistinguishable from random data.

Levels: each multiplication consumes one level; this circuit needs 4, so the scheme is configured with exactly 4.

Logit: the model's raw output (log-odds of default). The score is a straight-line rescaling of it, so no sigmoid is needed for the score.

Poly-sigmoid: a degree-3 polynomial approximating the sigmoid so a default probability can be computed under encryption (exact sigmoid isn't possible).

Factor points: how many points a factor adds/removes versus an average customer in the training data.
